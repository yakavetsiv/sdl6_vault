# Skill: Dark Futuristic Scientific Architecture Diagrams

## Purpose

Use this skill to generate clean, readable, high-impact scientific architecture diagrams for self-driving laboratories, agentic AI systems, automation workflows, biological model optimization, organ-on-chip platforms, and related AI-driven laboratory infrastructure.

The target visual language is a **premium dark futuristic scientific dashboard**: minimal, modular, readable, and presentation-ready. The style should feel like a high-end biotech keynote slide, not a dense engineering diagram.

---

## Core Visual Identity

### Overall Look

Use a modern scientific user-interface aesthetic with:

- dark navy or black background
- glassmorphism panels
- thin glowing borders
- subtle grid texture
- soft cyan, blue, purple, magenta, and orange accents
- clean line icons
- modular dashboard composition
- high contrast typography
- generous spacing
- clear hierarchy
- crisp vector-like rendering

The diagram should feel:

- scientific
- premium
- futuristic
- controlled
- intelligent
- clean
- credible
- scalable

Avoid:

- cartoon style
- clip art
- cyberpunk overload
- excessive neon
- overly decorative effects
- tiny unreadable labels
- busy technical clutter
- compressed typography
- narrow fonts
- photorealistic chaos
- excessive gradients
- too many icons in one panel

---

## Typography Rules

### Font

Use:

- Arial
- Arial Regular
- Arial Bold

Do not use:

- Arial Narrow
- condensed fonts
- decorative fonts
- handwritten fonts
- overly futuristic unreadable fonts

### Minimum Readability

For slide diagrams:

- Title: very large, bold, clear
- Section headers: large and bold
- Labels: readable at presentation scale
- Body text: short, minimal, and large enough to read
- Avoid paragraphs inside panels

Recommended label density:

- 1 title
- 3 to 6 major sections
- 1 to 3 short bullets per section
- no more than 5 to 8 words per bullet
- avoid long sentences

Use title case or sentence case consistently.

---

## Color Palette

### Background

Preferred:

- near-black: `#03070D`
- deep navy: `#07111F`
- dark blue-gray: `#0B1624`

Use subtle radial gradients only if they improve depth.

### Primary Accent Colors

Use these consistently:

- Cyan: `#28E6FF`
- Blue: `#2D8CFF`
- Purple: `#8A5CFF`
- Magenta: `#FF4FB8`
- Orange: `#FF6A00`
- Green, only sparingly for quality or success: `#34D399`

### AC / SDL Accent

For Acceleration Consortium or SDL diagrams, use orange as the main highlight:

- AC Orange: `#FF3D00`
- Secondary orange glow: `#FF8A1F`

### Color Assignment by Function

Use consistent semantic colors:

| Function | Color |
|---|---|
| User / human supervision | Orange |
| Experiment design | Cyan |
| Laboratory automation | Blue |
| AI analysis | Purple |
| Data and reporting | Magenta |
| Knowledge layer | Cyan or teal |
| Safety / policy | Orange or amber |
| Quality / success | Green |
| Warning / constraint | Amber or red, used rarely |

Do not use many colors randomly. Each color should indicate a function.

---

## Composition Rules

### Preferred Aspect Ratios

Use:

- 16:9 widescreen for slides
- 30 × 15 cm when requested by the user
- 31 × 10.7 cm for wide architecture banners
- 13 × 4.6 cm for compact strip diagrams
- transparent background only for icons or isolated assets

### Margins

Keep comfortable margins:

- at least 5 percent padding around the slide
- no text or icons touching edges
- avoid crowding at corners

### Layout Principles

Use one of these structures:

1. **Top-to-bottom layered system**
   - Natural interaction
   - Orchestration
   - Workflow stages
   - Knowledge layer
   - Human supervision

2. **Left-to-right workflow**
   - Design
   - Execute
   - Analyze
   - Report
   - Improve

3. **Hub-and-spoke agent system**
   - Central orchestrator
   - Specialized agents around it
   - Workflow stages below

4. **Modular dashboard**
   - 3 to 5 major panels
   - each panel has one role
   - arrows show relationships

5. **Closed-loop system**
   - objective
   - design
   - execute
   - analyze
   - update
   - next experiment

For a single slide, prefer **4 main workflow panels maximum** plus simple top and bottom layers.

---

## Recommended Architecture Layout

For agentic autonomous laboratory diagrams, use this standard layout:

### Top Layer: Natural Interaction

Show users interacting through:

- Chat
- Voice
- Image / Video
- Dashboard

Represent users as scientists, team members, or role icons.

Keep text concise:

- “Researchers and team members”
- “Chat”
- “Voice”
- “Image / Video”
- “Dashboard”

### Second Layer: System Orchestrator

A central system panel:

**System Orchestrator**

Short description:

“Understands goals, decomposes tasks, coordinates specialized agents.”

This should be visually central and important.

### Third Layer: Specialized Agents

Show specialized agents as a compact row of icons or cards.

Recommended agents:

- Planning Agent
- Lab Operations Agent
- Vision Analysis Agent
- Reporting Agent
- Knowledge Agent
- Safety and Policy Agent
- Interface Agent

Keep each agent card small.

Avoid long descriptions. Use short function labels only.

### Fourth Layer: Main Workflow

Use 4 large panels:

1. **Experimental Design**
   - optimize design
   - suggest protocols
   - predict outcomes
   - human approval

2. **Laboratory Automation**
   - execute protocols
   - monitor in real time
   - ensure quality

3. **AI Analysis**
   - detect and quantify
   - assess quality
   - generate insights

4. **Data and Reporting**
   - store and organize
   - summarize results
   - generate reports and dashboards

### Fifth Layer: Knowledge and Documentation

Use a single horizontal bar:

- Research Papers
- Laboratory Manuals
- Standard Operating Procedures
- Team Notes
- Technical Information
- Experimental History

This layer should feed into the orchestrator and agents.

### Bottom Layer: Human Supervision and Collaboration

Use a simple orange workflow:

Review → Approve → Adjust Priorities → Interpret Results → Collaborate

This layer should show that humans supervise and approve, while the system executes.

---

## Simplification Rules

When the diagram feels too complex, simplify in this order:

1. Remove detailed descriptions from agent cards
2. Replace paragraphs with 2 to 3 word labels
3. Reduce specialized agents to icons with names only
4. Use 4 workflow stages instead of 5 or 6
5. Merge data management and reporting into one panel
6. Merge knowledge sources into one horizontal bar
7. Replace detailed arrows with a few main arrows
8. Remove small sub-icons inside each panel
9. Increase whitespace
10. Increase text size

A clear diagram is better than a complete diagram.

## Text Rules

### Use Clear Terms

Prefer:

- Artificial Intelligence
- Laboratory Automation
- Data and Reporting
- Experimental Design
- Human Supervision
- Knowledge Layer
- System Orchestrator
- Specialized Agents

Avoid acronyms unless necessary.

Avoid or spell out:

- AI → Artificial Intelligence, unless space is limited
- BO → Bayesian Optimization
- SOPs → Standard Operating Procedures
- RAG → Retrieval-Augmented Generation
- CV → Computer Vision
- OOC → Organ-on-Chip

If acronyms are used, define them once.

### Keep Labels Short

Use short labels such as:

- “Design experiments”
- “Suggest protocols”
- “Execute workflow”
- “Analyze images”
- “Summarize results”
- “Approve actions”
- “Update priorities”

Avoid:

- long explanations
- complete sentences inside panels
- dense scientific text
- many parenthetical details

## Icon Style

Use thin, technical, line-based icons with subtle glow.

Preferred icon types:

- scientist / team members
- chat bubble
- microphone waveform
- image upload
- video frame
- dashboard screen
- brain or neural network
- robotic arm
- liquid handler
- incubator
- microscope / imaging system
- organ-on-chip device
- database
- report document
- book / papers
- checklist / procedures
- shield / safety
- graph / optimization surface

Icons should be:

- simple
- consistent line weight
- monochrome with accent glow
- not cartoonish
- not overly detailed
- aligned to panels

---

## Panel Design

Use rounded rectangular panels with:

- dark transparent fill
- thin glowing border
- subtle inner glow
- small icon
- short title
- 1 to 3 bullets or labels

Panel style:

- border radius: medium to large
- border glow: subtle
- fill opacity: low to medium
- avoid heavy drop shadows
- avoid dense texture

Panel hierarchy:

- main workflow panels: largest
- orchestrator panel: central, prominent
- agent cards: smaller
- knowledge bar: wide and low
- supervision bar: wide and low, orange

---

## Arrow and Connection Rules

Use arrows to clarify flow, not decorate.

### Main Flow

Use solid glowing arrows for the core workflow:

Experimental Design → Laboratory Automation → Artificial Intelligence Analysis → Data and Reporting

### Agent Routing

Use thin dotted or semi-transparent lines from orchestrator to agents and workflow stages.

### Feedback Loop

Use one large subtle orange or cyan loop from Data and Reporting back to Natural Interaction or Experimental Design.

Do not overuse arrows.

Avoid:

- crossing arrows
- too many bidirectional connections
- unclear spaghetti networks
- arrows that point to empty space
- arrows that visually compete with labels

---

## Visual Density Targets

For a single slide:

- 4 major workflow panels
- 1 orchestrator panel
- 5 to 7 agent icons
- 1 knowledge bar
- 1 human supervision bar
- 1 main feedback loop
- maximum 20 to 30 total labels

For a complex architecture slide:

- no more than 6 major zones
- no more than 8 agent cards
- no more than 5 workflow stages
- no more than 2 rows of small icons
- avoid more than 3 levels of hierarchy

---

## Organ-on-Chip Visual Rules

When representing organ-on-chip systems:

Use:

- transparent microfluidic chip
- channels with subtle cyan or red flow lines
- small cell/tissue region
- clean 3D or semi-isometric view
- minimal labels
- connection to optimization graph

Avoid:

- unrealistic organs floating inside chip unless stylized
- excessive biological detail
- crowded cell illustrations
- distracting textures

Good labels:

- “Organ-on-chip model”
- “Optimize design”
- “Suggest protocols”
- “Predict outcomes”
- “Human approval”

---

## Laboratory Automation Visual Rules

For laboratory automation panels, include only 2 to 4 device icons.

Preferred devices:

- liquid handler
- incubator
- imaging system
- robotic transfer arm

Use semi-isometric icons with minimal detail.

Avoid using too many device models in one panel.

Good labels:

- “Execute protocols”
- “Monitor in real time”
- “Ensure quality”

---

## Artificial Intelligence Analysis Visual Rules

Show analysis as a simple visual transformation:

Microscopy image → neural network → segmentation / graph / quality metric

Use 3 elements maximum:

- input image
- analysis model
- output result

Good labels:

- “Detect and quantify”
- “Assess quality”
- “Generate insights”

Avoid:

- deep network diagrams with many layers
- too many microscopy thumbnails
- unreadable charts
- excessive small labels

---

## Data and Reporting Visual Rules

Show:

- database icon
- dashboard screen
- report document

Good labels:

- “Store and organize”
- “Summarize results”
- “Generate reports”

The reporting agent should visually connect here.

Avoid:

- too many databases
- too many software logos
- complex backend infrastructure
- raw platform names unless required

---

## Knowledge Layer Visual Rules

Use a single horizontal bar with icons.

Recommended sources:

- Research Papers
- Laboratory Manuals
- Standard Operating Procedures
- Team Notes
- Technical Information
- Experimental History

Optional sources:

- Safety Policies
- Internal Data
- Knowledge Graph
- Protocol Library

Show this layer feeding the orchestrator and specialized agents.

Keep it visually calm and less dominant than the main workflow.

## Human Supervision Visual Rules

The human layer should be a supervisory control layer, not manual operation.

Use orange accents.

Recommended sequence:

Review → Approve → Adjust Priorities → Interpret Results → Collaborate

Good labels:

- “Review plans and results”
- “Approve experiments”
- “Set goals and constraints”
- “Extract insights”
- “Make decisions”

Keep the human layer at the bottom or top-left depending on the layout.

## Quality Checklist

Before accepting a generated diagram, check:

### Readability

- Are all major labels readable?
- Is the title clear?
- Are there no tiny paragraphs?
- Is the font non-condensed?

### Structure

- Can the viewer understand the flow in 5 seconds?
- Are there only 3 to 5 main modules?
- Is the orchestrator clearly connected to agents and workflow?
- Is the human role clear?

### Visual Hierarchy

- Does the most important idea stand out?
- Are colors used consistently?
- Are panels aligned?
- Is there enough whitespace?

### Scientific Accuracy

- Are laboratory automation, analysis, data, and reporting distinct?
- Are agents shown as driving the workflow, not isolated?
- Are knowledge sources connected to the system?
- Is human approval shown before execution when needed?

### Style

- Does it match the dark futuristic scientific UI style?
- Does it avoid cartoon and clip art?
- Does it look suitable for a scientific keynote or investor deck?

## Common Failure Modes and Fixes

### Failure: Too much text

Fix:
- remove descriptions from agents
- use names only
- reduce bullets to 2 per panel
- enlarge labels

### Failure: Agents appear disconnected

Fix:
- place orchestrator centrally
- connect agents to orchestrator
- connect orchestrator to workflow stages
- use subtle routing lines

### Failure: Diagram looks like software architecture only

Fix:
- add organ-on-chip, microscopy, lab instruments, and reports
- make biological workflow visible

### Failure: Diagram looks like manual lab workflow

Fix:
- make the system orchestrator dominant
- show agents driving each stage
- add feedback loop and human approval layer

### Failure: Too much cyberpunk

Fix:
- reduce neon intensity
- use cleaner panels
- increase whitespace
- use muted dark navy background
- remove decorative glowing particles

### Failure: Text is unreadable

Fix:
- request Arial only
- no condensed fonts
- fewer words
- larger labels
- higher contrast
- fewer panels

# Strict Reference Style: Matching the SDL Dark Scientific Panel Look

Use this section when the user asks for diagrams to match the uploaded SDL-style dark scientific infographic.

## Mandatory Style Consistency Rules

All generated schematics should preserve the same visual language across projects:

- same dark scientific dashboard mood
- same typography behavior
- same cyan section titles
- same rounded rectangular panel design
- same numbered panel badges
- same thin glowing borders
- same color hierarchy
- same modular three-panel or four-panel layout logic
- same bottom summary strip style
- same balance between icons, microscopy images, and short explanatory labels

The output should look like it belongs to the same slide family.

---

## Mandatory Font Rules

Use **Arial everywhere**.

Allowed:

- Arial Regular
- Arial Bold
- Arial Italic only if absolutely necessary

Forbidden:

- Arial Narrow
- any condensed font
- any compressed font
- futuristic decorative fonts
- serif fonts
- handwritten fonts
- mixed font families

Minimum text size rule:

- No text smaller than **8 px**
- Prefer 10 to 16 px for labels
- Prefer 18 to 26 px for section headers
- Prefer 30 px or larger for major slide titles

Do not allow tiny annotation text. If there is not enough space, remove text rather than shrinking it.

Prompt phrase to include:

```text
Use Arial font everywhere. Do not use Arial Narrow, condensed fonts, compressed fonts, or any text smaller than 8 px.
```

---

## Numbering Style

Use the same numbered panel badge style throughout the diagram.

### Panel Badge Design

Each major section should start with a letter and title, such as:

- **A. AUTOMATED MONITORING WORKFLOW**
- **B. BIOLOGICAL INPUTS AND GROUND TRUTH**
- **C. MODEL ARCHITECTURE**
- **D. DATASET SUMMARY**

or for workflow steps:

- **1**
- **2**
- **3**
- **4**

### Badge Appearance

For numbered panels, use:

- circular badge
- cyan or module-color outline
- dark transparent fill
- subtle inner glow
- white or cyan number
- bold Arial number
- badge placed at the top-left corner of the panel
- badge aligned with the section title
- consistent size across all panels

For lettered section titles, use:

- cyan bold uppercase letter
- period after the letter
- uppercase title text
- same baseline alignment
- technical condensed-looking layout is forbidden; use normal-width Arial

Example visual format:

```text
A. AUTOMATED MONITORING WORKFLOW
B. BIOLOGICAL INPUTS AND GROUND TRUTH
C. MODEL ARCHITECTURE
D. DATASET SUMMARY
```

If using numbered workflow panels, combine a circular badge plus a title:

```text
[ glowing circle 1 ] EXPERIMENTAL DESIGN
[ glowing circle 2 ] LABORATORY AUTOMATION
[ glowing circle 3 ] ARTIFICIAL INTELLIGENCE ANALYSIS
[ glowing circle 4 ] DATA AND REPORTING
```

Do not use inconsistent numbering shapes across panels.

---

## Title Style

Use a clean scientific slide title style.

Title should be:

- large
- bold Arial
- high contrast
- preferably white or AC orange
- left aligned or centered depending on layout
- not compressed
- not decorative
- not more than one line unless necessary

For panel-heavy scientific figures, section headers should use:

- cyan color
- uppercase Arial Bold
- letter prefix when appropriate
- thin separator lines between major columns

Recommended title colors:

- white for global figure title
- AC orange `#FF3D00` for strategic architecture titles
- cyan `#28E6FF` for panel section titles

---

## Panel and Box Effects

Use the same box treatment across the full schematic.

### Panel Fill

- black or very dark navy transparent fill
- subtle blue-green gradient only if needed
- avoid heavy texture
- avoid bright filled boxes

Recommended fill:

- `rgba(3, 7, 13, 0.78)`
- `rgba(7, 17, 31, 0.75)`

### Panel Border

- thin 1 to 2 px border
- cyan, blue, purple, magenta, or green based on function
- subtle glow
- rounded corners

Do not use thick borders.

### Inner Cards

For sub-steps inside a column:

- stacked rounded rectangles
- same width
- consistent vertical spacing
- left icon area
- right text area
- small downward arrows between stacked steps

This is preferred for workflow pipelines.

### Separators

Use thin vertical separator lines between major panels.

Use subtle cyan-gray lines, not bright white.

---

## Color Scheme Consistency

Use the following color mapping.

| Element | Color |
|---|---|
| Section headers | Cyan `#28E6FF` |
| Primary workflow borders | Cyan / blue |
| Model architecture border | Purple `#B45CFF` |

| Data and reporting | Magenta `#FF4FB8` |

| Secondary body text | Light gray |

Use green only for biological signal, quality pass, or ground truth.

Use orange only for human supervision, feedback loops, regression trends, or AC emphasis.

Avoid random colors.

---

## Layout Style Matching

For figures similar to the reference image, use this layout:

### Top Area

Three major panels across the slide:

1. Left panel: workflow or process
2. Middle panel: biological inputs, image examples, or ground truth
3. Right panel: model architecture, analysis, or outputs

### Bottom Area

One full-width summary bar:

- dataset summary
- key statistics
- platform capabilities
- major takeaways

This bar should use:

- thin cyan border
- multiple stat blocks separated by vertical dividers
- large cyan numbers
- simple line icons
- short labels

### Panel Proportions

Recommended:

- Left panel: 28 to 32 percent width
- Middle panel: 35 to 40 percent width
- Right panel: 28 to 32 percent width
- Bottom summary bar: full width, 18 to 22 percent height

Do not overload the bottom bar. Use 4 to 6 summary blocks maximum.

---

Each stat block should contain:

- simple cyan line icon

Use vertical dividers between stat blocks.

Avoid small paragraphs.

---

## Image Tile Style

For microscopy or example image panels:

- use square or rectangular image tiles
- thin white or cyan border
- slightly rounded corners
- same height and width across tiles
- labels above each tile
- label color follows data type

Recommended label colors:

- Brightfield: cyan
- Phase Contrast: white
- Ground Truth / GFP: green
- Prediction: purple or magenta
- Quality metric: green

Do not place long text over the images.

---

## Model Architecture Style

For model architecture panels:

- show input image tiles at the top
- show plus sign or arrow between inputs
- show one central model encoder block
- show output heads below
- use three task-specific boxes if needed

Preferred structure:

```text
Input Images
↓
```

This section OVERRIDES older SDL publication-style guidance when generating agentic system schematics.

The canonical visual target is:

## “Agentic AI System for Autonomous Organ-on-Chip Discovery”

All future architecture diagrams should strictly follow this visual language unless explicitly instructed otherwise.

This style is now considered the PRIMARY reference style.

# Core Identity

The diagram should feel like:

- an advanced scientific operating system
- an AI orchestration platform
- a modular autonomous laboratory ecosystem
- a keynote-ready scientific systems architecture
- a premium biotech software + automation platform

The diagram should NOT feel like:

- a dense scientific poster

- a publication methods panel

- a computational graph
- a software backend architecture map

## clarity → orchestration → hierarchy → readability → modularity

## density → completeness → technical detail
